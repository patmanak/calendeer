# Legacy title UPDATE compatibility

Fresh supported edits use [personal-v2](PERSONAL_UPDATE.md). The bridge no longer
prepares or dispatches title-only legacy work. Retained capsules, bare reservations
and PREPARED requests are explicitly reported as unsupported for sending; their
original content and immutable identities remain stored.

UNKNOWN work keeps its original adapter format, protected request and identity.
Only readback inspection may obtain a verified result. Existing facts may complete
the exact historical Android/SQL acknowledgement, including transferred CREATE
provenance, without preparing, claiming or sending another request. A completed
proof/ACK releases only the qualified event owner for a distinct personal edit.

Read-only metadata discovery includes previous generations and displays retained
issues even when the calendar is paused or calendar permission is missing. It
never grants ownership or authorizes a submission. Full historical proof and
admission checks remain mandatory for recovery and personal ownership.

## Repeatable verification

The SQLite and Provider compatibility fixtures retain frozen title/text/time
formats and test interruption, exact acknowledgement, generation isolation and
UNKNOWN inspection. Synthetic historical state construction stays in test code.
The current milestone's live/client campaign uses personal-v2; earlier experimental
write journeys in [validation](VALIDATION.md) are frozen historical evidence.
